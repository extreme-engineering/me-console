## 二、市场判断

三个正在发生的趋势与 MeOS 的交点：

1. **AI Agent 时代，个人数据需要可被机器读写的入口** —— MCP 已成为事实标准，MeOS 是少数「生活数据 × MCP」的本地实现
2. **数据主权意识觉醒** —— 健康笔记聊天记录散在各大 App，用户开始想要「属于自己的本地数据库」
3. **个人操作系统（Life OS）品类被 Notion 模板教育成熟**，但模板方案无数据层、无 AI 读写、无闭环

MeOS 不和任务管理工具抢用户，而是占据「**个人生活数据操作系统**」这个尚无强势玩家的空位。

## 三、GTM 总策略

> **双轮驱动 + 标准先行**：以开源社区建立信任，以创始人 build-in-public 内容带来声量，用 MeLog Standard 把用户变成生态共建者。

| 要素 | 选择 | 理由 |
|---|---|---|
| 进入动作 | PLG（产品驱动增长）+ 社区 | 自托管工具无法靠销售；开发者/极客是天然种子层 |
| 首发人群 | AI 尝鲜者 + 生产力极客（见 [02-personas](./02-personas.md)） | 对 local-first / MCP 敏感，能容忍安装门槛，产出反馈与内容 |
| 核心渠道 | GitHub + 创始人自媒体矩阵 + 技术社区 | 创始人已有品牌板块与 9 平台手册，是零成本差异化优势 |
| 生态钩子 | MeLog Standard + 连接器/技能清单格式 | 标准 = 他人贡献的理由，也是护城河 |
| 商业化节奏 | 延后（Phase 4），先证明活跃 | 见 [03-pricing](./03-pricing.md)，过早收费会杀死社区信任 |

## 四、阶段路线

与仓库路线图（README 路线图）对齐，每阶段有明确 gate，未达标不顺延：

| 阶段 | 时间窗 | 目标 | 北极星（代理） | 关键动作 | 进入下一阶段的 Gate |
|---|---|---|---|---|---|
| **Phase 0 备战** | T+0 ~ 4 周 | 补齐分发资产 | — | Landing page、demo GIF、Docker 一键起、内测 10 人 | 10 个种子用户完成首次完整使用（≥1 次反思 + 1 个 MeLog 数据源） |
| **Phase 1 冷启动** | 第 1–3 月 | 开源社区破圈 | GitHub Star | OSS 发布（V2EX / 即刻 / Show HN / Product Hunt）、每周 build log、招募贡献者 | Star ≥ 500 且周均 issue/PR ≥ 5 |
| **Phase 2 增长** | 第 4–9 月 | C 端留存与口碑 | 周活跃安装数（opt-in 统计上线） | Onboarding 打磨、模板/技能内置案例、分享物（平衡轮海报/年度报告）、云托管 beta | opt-in 周活 ≥ 1000，30 日留存 ≥ 25% |
| **Phase 3 生态** | 第 10–18 月 | MeLog Standard 成为第三方默认接入格式 | 第三方连接器 / 技能数量 | Skill 市场原型、开发者文档、2–3 个标杆合作 | 第三方连接器或技能 ≥ 20 |
| **Phase 4 商业化** | 18 月+ | 可持续收入 | 免费转付费率 | 云托管/Pro 订阅上线（定价见 pricing 分册） | 付费转化 ≥ 3% 且不伤害社区口碑 |

> 多端（Mac 原生 / 小程序）在 Phase 2–3 按留存数据决定优先级，不为功能而功能。

## 五、差异化打法：GTM 与品牌板块共用一套内容引擎

MeOS 的独特之处：创始人的自媒体 IP（FDE 田野调查，见 [docs/实践/品牌/总览.md](../docs/实践/品牌/总览.md)）本身就是产品最大的渠道。

- **产品即内容**：MeOS 的开发过程按 build-in-public 拆成系列内容（定位→架构→MeLog 接入→发布），素材直接来自 git 历史与 DESIGN.md
- **内容即获客**：每期内容片尾带 GitHub 地址；「帮创业者用系统经营人生」的人设与产品互为证明
- **用户即演员**：早期用户的真实使用反馈是田野调查素材，反哺产品与内容（闭环见 [04-channels](./04-channels.md)）
