# MeLog 安全与数据边界

> MeLog 汇聚的是一个人最敏感的生活数据（聊天记录、健康、笔记）。
> 这份文档说明当前的边界设计、已知风险与推荐配置，是产品承诺的一部分。

## 1. 威胁模型（简版）

| 资产 | 主要威胁 | 当前对策 |
| --- | --- | --- |
| 本地 SQLite（meos.db） | 文件被拷贝 / 设备丢失 | 见 §3 静态加密现状 |
| 云端同步（可选层） | 敏感数据上云后的泄露与合规 | 数据分层边界（§2） |
| 连接器写入通道 | 令牌泄露后被批量写入/覆盖 | 连接器令牌最小权限（§4） |
| LLM 技能运行 | 数据外发给第三方端点 | 仅发往用户配置端点；上下文截断；边界分类默认不参与（§5） |
| API 访问 | 越权读写 | JWT + dev 旁路仅限非生产（§6） |

## 2. 数据分层边界（云端是可选层）

- 本地 SQLite 是第一存储；云端（Supabase 等）只是可选同步层。
- **敏感分类（当前为 `im`）默认不进入云端读写**：云端读取被过滤、显式读取返回 403、
  写入通道（ingest/capture/MCP）在云端不可用。
- 放开边界需要显式配置：Web 端以 `VITE_MELOG_CLOUD_SENSITIVE=true` 构建，风险自担。
- 规范条目见 [标准 · §8 数据边界](./标准.md)；敏感分类清单的变更必须在标准文档登记。

## 3. 静态加密现状（诚实的部分）

- 当前 SQLite 文件**未加密**（Prisma 5 默认驱动不支持 SQLCipher）。
- 缓解措施（用户侧，强烈建议）：
  - 打开操作系统全盘加密（macOS FileVault / Windows BitLocker / Linux LUKS）；
  - 不要把 `packages/api/src/prisma/meos.db` 放进任何同步网盘的目录；
  - 备份走加密介质。
- 路线图：若上 SQLCipher 需要更换 Prisma datasource 驱动（社区 `@prisma/adapter` 方案），
  属破坏性迁移，需单独评估；在此之前全盘加密是官方推荐姿态。

## 4. 连接器令牌（最小权限）

- `POST /api/melog/tokens {name, sourceId?}` 创建 `melt_…` 令牌，**明文只在创建响应中出现一次**。
- 令牌只能调用 `POST /api/melog/ingest`；绑定数据源后不能写其他源、不能内联新建源。
- `GET /tokens` 只显示元数据与哈希前不显示明文；`DELETE /tokens/:id` 即时吊销。
- 实践：为每个连接器/脚本发独立令牌，最小绑定，定期轮换，泄露即吊销。

## 5. LLM 技能运行

- 条目上下文只会发送到 `MELOG_LLM_BASE_URL` 指向的用户自配端点（本地 Ollama 亦可）。
- 上下文按条目截断（content ≤400 字符），条目 ID 不进入 prompt，但 `entryIds` 保留在
  运行记录中供审计。
- 回退策略：LLM 失败自动回退规则引擎，报告中注明。
- 超时与上下文预算可调：`MELOG_LLM_TIMEOUT_MS`（默认 60s）、`MELOG_LLM_MAX_ENTRIES`（默认 200）。

## 6. API 访问

- 生产必须设置 `JWT_SECRET`（服务启动强制校验长度与来源）。
- 开发旁路（`mock-user-1`）仅在 `NODE_ENV=development` 或显式 `MEOS_DEV_AUTH=true` 时启用；
  生产构建不会出现。
- 调度器为 API 进程内单实例设计（60s 轮询）；如多实例部署需外置调度（见路线图），
  当前请保证每个数据目录只有一个 API 实例。
