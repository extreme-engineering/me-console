# MeOS 文档中心

> 全仓库文档地图与导航。产品介绍与快速启动见 [根 README](../README.md)。

目录与文件用中文命名。顶层四个目录中，前三个按「**这句话回答的是什么问题**」分层，第四个只放资源：

| 层 | 回答 | 判据 | 变化速度 |
|----|------|------|----------|
| [理论/](./理论/) | 为什么 · 是什么 | 不描述本仓库的实现：方法论、外部知识库、调研证据 | 慢，可长期复用 |
| [实践/](./实践/) | 现在怎么干 | 板块文档与规范、手册、SOP、模板、脚本 | 随板块迭代 |
| [档案/](./档案/) | 做过什么 | 一次性过程记录，写完即冻结 | 只增不改 |

四条命名约定：

- **`README.md` 保留英文**。GitHub 靠它渲染文件夹首页，改成中文名后点进目录就没有导航页了 —— 本文件与各知识库的索引同理。
- **`FIELD_LOG_001_SHOTLIST.md` 保留英文**。[选题库](./实践/访谈IP/选题库.md) 正文里明确记了这条决定：改名会牵动 `render-brand-cards.py` 与已出图的 `*-001.png` 资产，零收益。
- **编号知识库整块保留**。[理论/知识库/](./理论/知识库/) 下每个库的 `01-10` 编号即推荐阅读顺序，拆开会破坏它 —— 因此 [个人IP/05-实战/](./理论/知识库/个人IP/05-实战/) 这类「库内的实战篇」留在理论层，不外提。
- **[资产/](./资产/)** 挂在根：既非理论也非实践，且 [scripts/render-brand-cards.py](../scripts/render-brand-cards.py) 固定输出到 `docs/资产/品牌/`。

## 理论层：五维框架

五维框架是 MeOS 的理论基石，将人生管理划分为五个相互关联的维度。

| 维度 | 核心问题 | 关键产出 | 管理频率 |
|------|----------|----------|----------|
| **方向** | 我要去哪里？ | 愿景、领域、目标、心态 | 季度校准 |
| **行动** | 如何做到？ | 待办、习惯、日程 | 每日执行 |
| **认知** | 如何理解？ | 课题、洞察、阅读 | 持续积累 |
| **反思** | 学到了什么？ | 经验、模式、智慧 | 日/周/月/年 |
| **资源** | 凭什么支撑？ | 健康、人脉、工具 | 定期维护 |

核心原则：**方向优先于行动 · 微小一致地执行 · 知识需要转化 · 未经审视的经验只是经历 · 失去健康其他维度无从谈起**。

维度速查（路径相对 [理论/方法论/](./理论/方法论/)）：

```
方向 → 我要去哪里？        行动 → 如何做到？         认知 → 如何理解？
├── 愿景.md  愿景构建       ├── 待办.md   GTD 待办     ├── 课题.md 课题研究
├── 领域.md  八领域模型     ├── 习惯.md   习惯养成     ├── 洞察.md 洞察提取
├── 目标.md  OKR 目标       └── 日程.md   时间块       └── 阅读.md  高效阅读
└── 心态.md  核心心态

反思 → 学到了什么？         资源 → 凭什么支撑？
├── 每日复盘.md  每日复盘    ├── 订阅.md    订阅管理
└── 周期复盘.md  周期复盘    ├── 人脉.md    人脉建设
                             └── 健康.md    健康追踪
```
